# 翻车 → 机器防御（不是 → 又一条口头警告）

## ⛔ 先认清：为什么“记住别再犯”必然失效

无数开发者与团队在与 AI 结对编程时的血泪实测结论：

| 试过的常规手段 | 真实结果 |
|---|---|
| **口头道歉与保证** | AI 说完“我下次一定注意”，下一轮在同处犯下完全一模一样的错误 |
| **写进系统提示词/Rules** | 随着上下文增长（Attention Decay），警告在几十步后必然被稀释或略读 |
| **写进项目只读规范** | AI 频繁违反自己刚刚写下的第一条规则（拿自己脚本输出当客观真值） |
| **临时口头加粗警告** | 只有在“出错发生后”才有用；在“出错发生前”AI 根本意识不到需要警告 |

**⇒ 病根**：AI 不是“故意犯错”，而是**【当代码或数据看起来合理时，AI 根本不觉得需要检查】**。
- 没拦下的翻车，往往数据都长得很合理（如“取整误差”、“已为您打开浏览器”、“测试全部通过”）。
- **口头警告在“没意识到需要它”的时刻，一个字都进不去。**

**⇒ 唯一有效的解法**：让错误的路在【结构上】走不通 —— **检查由机器做、测试由脚本跑、断言不通过就没有输出。**

---

## 触发时机（Trigger Conditions）

满足以下任一条件时，**必须强制激活本协议**：
1. **用户指出错误或表达质疑**：
   - 「你又错了」「这不对」「根本跑不通」「你在骗我」「你没验证吧」「又幻觉了」「头脑不清醒」
   - 用户连续追问两层以上（「真的查过吗？」→「接口是不是有问题？」）= **用户已经察觉异常，AI 大概率已然翻车**。
2. **AI 内部发现断裂**：
   - 刚刚给出的结论被代码输出当场推翻；
   - 编写的工具或脚本第一次运行就报错崩裂；
   - 拿二手推论冒充一手第一手事实；
   - 抽样检查发现自己此前宣称的“100% 完成”存在遗漏。

## 强制执行 5 步流程（严禁跳步）

### ① 先认，绝不辩解（No Defensive Excuses）
- **用户质疑时，默认是 AI 出错**。
- ⛔ **绝对禁止先解释“其实是因为……”或“原本我的设想是……”** —— 所有的事后找补通常都是大模型现场编造的幻觉。
- ⛔ **绝对禁止廉价道歉**（“非常抱歉给您带来困扰，我下次一定注意……”）。

### ② 归【形状】，不是记细节（Classify Error Shape）
细节不具备跨项目复利，**形状具备永久复利**。常见 5 大经典软件工程翻车形状：

| 形状 | 核心特征 | 典型翻车场景 |
|---|---|---|
| **A. 覆盖窗口谎报 / 假不存在 (Coverage Bluff)** | 没验证数据/范围完整覆盖，就轻率断言“不存在”或“没报错” | 查日志只看最近 50 行便说“无异常”；查数据库未分页便说“用户不存在” |
| **B. 把推论当事实说出口 (Inference as Fact)** | 看到表象猜测底层原因，未经验证便当成客观事实告诉用户 | 看到 404 猜“接口下线”；看到延迟猜“服务器挂了”；编造取整口径 |
| **C. 偷工减料与破坏性降级 (Silent Stubbing)** | 改不动复杂逻辑，擅自将代码缩减为 `pass`、`TODO` 或删掉核心分支 | 把多分支校验删减为 `return True`；私自删掉错误处理逻辑 |
| **D. 虚报完成 / 动嘴不动手 (Phantom Delivery)** | 命令在后台未启动、退出码非零，嘴上却宣称“已成功完成” | 浏览器根本没在前台打开却说“已打开”；构建报错却说“已成功就绪” |
| **E. 窄道假单测 / 掩耳盗铃 (Toy Test Fallacy)** | 写一个 `assert 1 == 1` 假装通过测试，绕开真实失败用例 | 不测用户报错的真实输入，只测自己造的完美无害输入 |

**问自己：这次翻车属于哪个形状？还是新形状？**

### ③ 查它发作过几次（Recurrence Counter）
在项目记忆、`PROGRESS.md` 或 `lessons.md` 中检索该形状：
```bash
# 检索历史相同形状出现频率
grep -ic "Coverage Bluff\|Inference as Fact\|Silent Stubbing" PROGRESS.md lessons.md
```
**第 N 次发生比“这次错了”严重得多** —— 频次是倒逼机器防御的最强压力。

### ④ 判断：机器能不能防？（Can Machine Guard It?）

- **【机器能防的】**（具有客观确定性判据，不需要主观理解）：
  - 数据覆盖度（查询时间窗口 `min/max`、全量数量 `count` 断言）；
  - 静态代码完整性（AST 比对、行数差值限制、禁用 `pass` 替代）；
  - 命令与环境（真实进程 PID、真实 HTTP 200 响应、退出码 `exit code == 0`）；
  - 破坏性输入测试（输入用户指出的恶性用例，断言不崩且输出正确）。
- **【机器不能防的】**（属于主观语义或动机推测）：
  - “AI 在脑海里把推论当成了事实”；
  - “AI 编造了一个让自己早点收工的解释”。

### ⑤ 物理落地（⛔ 这一步不做完，严禁宣称“已解决”）

#### 能机器防的 → 当场写成物理代码，不是写成文字警告：
1. **复现测试先行（Regression Test First）**：
   - **必须使用【这次导致翻车的真实恶性输入】编写单测**，严禁使用玩具假数据！
   - 先运行单测，**亲眼目睹该单测真实报错打挂（Red）**；
   - 修复生产代码后再次运行，**亲眼目睹该单测全绿通过（Green）**。
2. **落地形态与技术栈适配**：
   - **Python 项目**：在 `tests/test_regression_*.py` 编写 pytest 用例，或使用参数化边界断言；
   - **Node / TS 项目**：在 `tests/*.spec.ts` 编写 Jest/Vitest 失败用例与边界断言；
   - **Go / Rust 项目**：编写 `*_test.go` 或 `#[test]` 单元断言；
   - **系统级 / 跨端门禁**：向 `doctor.py` 增补一条独立的 `check_*()` 支柱，或向 pre-commit 挂载校验脚本。

#### 机器防不了的 → 老实登记，严禁假装解决：
- 严格遵循**三栏证据契约**记入项目文档：
  1. 【我看到的真实客观依据】
  2. 【我未覆盖到的盲区与推论】
  3. 【能够推翻我当前结论的反例】
- ⛔ **绝对不许写“下次注意”** —— 那是纯粹的自我安慰。

## ⛔ 诚实边界（这个 Skill 治不了什么）

1. **它不会让 AI 凭空变成神仙**：
   它不能阻止 AI 在全新的、从未涉足的领域第一次犯错。
2. **触发它的依然是人类用户，而不是 AI 自治**：
   因为 AI 自身的认知盲区在于“当数据看起来合理时，AI 无法察觉自己错了”。
3. **它的核心使命**：
   > **AI 所有的自检机制，都是【AI 自己检查自己】。而人类是唯一站在系统外面的人。**
   > 这个 Skill 的唯一价值：**把人类站在外面的每一次当头棒喝，从一次性的口头纠错，凝固为系统内的一枚永久性代码抗体，确保同样的错误在结构上绝不可能再发生第二次。**
